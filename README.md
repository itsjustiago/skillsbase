# skillsbase

On-demand catalog of Claude Code skills, designed to be consumed by an agent (the `skill-matchmaker` skill) and installed locally per-project at `<project>/.claude/skills/`.

## Why this exists

Claude Code loads all globally-installed skill descriptions into every session's system prompt, eagerly. With many plugins enabled that burns tens of thousands of tokens before the first message. This repo holds skills that are only useful in specific projects, so they can be installed selectively — keeping the global setup lean.

See the architecture diagram in the [parent plan](https://github.com/itsjustiago/skillsbase/blob/main/docs/architecture.md) for the full design.

## How it works

1. `~/.claude/skills/skill-matchmaker/` lives globally and is always available.
2. When invoked (plan mode, `/skills-suggest`, or reactively), it:
   - Fingerprints the current project (reads `package.json`, lock files, key configs).
   - Fetches [`catalog.json`](./catalog.json) from this repo.
   - Scores each skill against the fingerprint.
   - Proposes a subset for installation.
3. On approval, the matchmaker writes selected `SKILL.md` files to `<project>/.claude/skills/<name>/SKILL.md`.
4. User restarts Claude — skills are now loaded for that project only.

## Catalog format

Every skill lives at `skills/<name>/SKILL.md` with YAML frontmatter:

```yaml
---
name: skill-name
description: One-line purpose, used for matching and surfaced to the agent.
tags: [tag1, tag2]
project_types: [nextjs, react]
when_to_use: |
  Concrete trigger conditions.
cost_tokens: 1500
---

# Body of the skill...
```

The machine-readable index ([`catalog.json`](./catalog.json)) is regenerated by `scripts/build-catalog.mjs` after any skill change.

## Profiles (starter packs)

`profiles/<name>.json` lists curated skill bundles for common project types. The matchmaker may use these as a baseline before refining with project-specific signals.

## Adding a new skill

1. Create `skills/<your-skill>/SKILL.md` with the frontmatter above.
2. Run `node scripts/build-catalog.mjs` to regenerate `catalog.json`.
3. Commit and push. The matchmaker fetches from the `main` branch.
